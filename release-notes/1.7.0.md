# Release notes for pkpdutils 1.7.0

## Features

- The uncertainty of a group curve is computed by the rust kernel. The parametric bootstrap and the delta method of `nca()` run inside the call which computes the parameters (`pkpdutils-core` 0.6.0), so a group batch takes one round trip instead of two and the differential gate of the two engines now compares every uncertainty variable it reports, variable by variable, within the same call.
- The draws of the bootstrap come from the kernel on both paths, the dispatched one and the python core, and are a pure function of the seed and the index (Philox4x64-10, `pkpdutils_core.bootstrap_normals`): a seed gives one answer whichever engine ran, on every platform, in a browser and across numpy releases. `numpy.random.Generator.standard_normal` promises its stream only on the same build, in the same environment, on the same machine, and reserves the right to change a distribution method, which is why the draws moved.
- `nca()` resolves the method of the uncertainty and draws the seed of a bootstrap before it dispatches, and both travel into `NCAResult.attrs["nca_options"]`. A run which was given no seed can therefore be repeated exactly as it ran, which it could not before.

## Changes

- **The numbers of a bootstrap moved.** Every `x_sd`, `x_se`, `x_ci_low`, `x_ci_high`, `x_pi_low`, `x_pi_high`, `x_geomean` and `x_geocv` of a bootstrap changes by the sampling difference between two sets of draws, the Monte Carlo error of `n_boot` replicates and nothing else: the point estimates, the delta method and `summarize` are untouched. A test or a document which pins a bootstrap number has to be regenerated against this release.
- The floor of the kernel is `pkpdutils-core>=0.6.0,<0.7`, and it is a contract floor: the draws of the bootstrap are `pkpdutils_core.bootstrap_normals`, which 0.5.1 does not carry, on both engines.

## Fixes

- The delta method of a multiple dose curve wrote its uncertainty columns before the per-interval variables in the dispatched engine, so the variables of a result were in a different order than the python core reports them. The order is python's on both paths.
- The uncertainty of a batch whose values are not in the canonical unit of a parameter (`ng/ml`, `l/min`) was off by the factor between the two units in the dispatched engine: a replicate is now scaled into the unit its column reports, as the point estimate is. Found by the differential gate, on `cl_f_sd` of a `ng/ml` batch.
