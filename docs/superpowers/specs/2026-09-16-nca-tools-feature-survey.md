# Non-compartmental analysis tools: feature survey and suggested features for pkpdutils

Date: 2026-09-16. Status: read-only survey, no code change. Scope: what the other non-compartmental analysis (NCA) tools compute and offer, what `pkpdutils` 1.1 already covers, and a prioritized list of features with an effort estimate and the module they would live in.

Twenty-two tools and packages were surveyed across five ecosystems (R, commercial desktop, Julia, python, and the bioequivalence statistics adjuncts). Every claim below is either taken from a page listed under [References](#references) and read during this survey, or read from the source tree of this repository. Where a claim could not be verified from a primary source it says so explicitly; nothing here is filled in from memory. Several widely repeated beliefs turned out to be wrong when checked against the primary documentation, and those corrections are called out where they matter.

## 1. Tools surveyed

**R, the NCA engines.** `PKNCA` (Bill Denney, AGPL-3, CRAN 0.12.1 of 2025-08-19, the de facto open source reference implementation, about 110 parameters), `NonCompart` (Kyun-Seop Bae, GPL-3, 0.8.3 of 2026-08-21, base R only, WinNonlin parameter naming), `ncar` (0.7.1 of 2026-08-27, the PDF and RTF reporting layer over NonCompart with IQ/OQ qualification and digitally signed reports), `pkr` (0.1.6 of 2026-07-30, WinNonlin slope selection criteria and bioequivalence forest plots), `ncappc` (Uppsala, 1.0.0 of 2025-04-25, NCA plus simulation based posterior predictive checks of a population model), `qpNCA` (qPharmetra, CRAN 1.1.6 stale at 2021-08-16 but the GitHub tree is active to 2026-02-07), `openNCA` (Pfizer's S-PLUS eNCA port, MIT, last real commit 2021-09-28, never on CRAN, effectively abandoned), and `PK` (the sparse and batch design estimators of Bailer, Nedelman, Holder, Jaki and Wolfsegger).

**R, the front ends on PKNCA.** `aNCA` (pharmaverse, Apache-2.0, CRAN 0.1.0 of 2025-12-09, Roche funded, a Shiny app with interactive slope selection and CDISC ADNCA/PP/ADPP output), `ubiquity` (BSD-2, CRAN 2.1.0 of 2025-01-07, a preclinical reporting wrapper that exports `AUC_Bailers_method` and writes Word and PowerPoint through `onbrand`), and `ruminate` (the same author's Shiny front end, which calls PKNCA directly rather than through ubiquity).

**Commercial.** `Phoenix WinNonlin` (Certara) and `PKanalix` (MonolixSuite, Simulations Plus). `Pumas` NCA (PumasAI) is commercial as well: Pumas went closed source at 2.0 and `PumasAI/NCA.jl` is no longer public.

**Julia, open source.** `MetidaNCA.jl` (MIT, v0.7.1 of 2025-07-02, the only credible open Julia NCA).

**Python.** There is no established python NCA package, and this is worth stating precisely because it defines where `pkpdutils` sits. `pharmpy-core`, the only python pharmacometrics package with meaningful adoption (about 4070 downloads a month, very active), has **no NCA at all**: a code search over `pharmpy/pharmpy` for "noncompartmental" and for `nca` in a path returns zero hits, and its tool list is entirely population model building. The names `pknca`, `nca`, `pyPKNCA` and `pkpdapp` are all unclaimed on PyPI, and a grep of the full 892210-name PyPI index for `pknca|noncompart|non-compart|nonmem|nlmixr` returns nothing. What does exist: `OpenPKPD` (AGPL-3, the most complete of them, with an `NCAEngine`, sparse, urine, bioequivalence and CDISC PP modules, and cross-validation against PKNCA on theophylline and WinNonlin on Indometh, but 1 GitHub star, one author, created 2026-05-07, about 60 downloads a month), `openpkflow` (MIT, per-subject NCA with three AUC methods, five BLQ methods, CDISC PP export, cross-validated against PKNCA 0.12.1 within 2 %, but no steady state parameters at all, 2 stars, about 120 downloads a month), `neopkpd` (a python wrapper over a Julia core, 0 stars, about 17 downloads a month), `pkpdapp` (a 294-line numpy `NCA` class inside an Oxford Django app, active but not importable as a library and not on PyPI), and `PKPy` (a research artifact with no licence file and not on PyPI). Combined downloads of every python package that computes an AUC from a curve are roughly 230 a month. The `awictor/noncompartmental` repository that a web search describes as a pure standard library python NCA **returns 404** and could not be verified.

**Bioequivalence statistics adjuncts.** `PowerTOST` and `replicateBE`, included because they define what "complete" means on the statistics side.

**Verified negative.** There is no `Certara.NCA` and no `certara.github.io/R-NCA`: that URL returns 404, and an enumeration of the 35 repositories of the `certara` GitHub organization and the 11 packages on `certara.r-universe.dev` contains no NCA package. Certara keeps NCA inside commercial Phoenix.

### 2.3 Regulatory and standards expectations

**ICH M13A** (Step 4, adopted 2024-07-23, issued by FDA 2024-10-31) is the harmonized baseline and is precise about what an NCA must deliver.

- Single dose, primary parameters for the bioequivalence analysis: `AUC(0-t)` and `Cmax`, plus early exposure parameters where applicable.
- Single dose, additional parameters to assess acceptability: `AUC(0-inf)`, `AUC(0-t)/AUC(0-inf)`, `tmax`, `kel`, `t1/2`.
- Acceptability rule, verbatim: "For single-dose studies, AUC(0-t) should cover at least 80% of AUC(0-inf). If the AUC(0-t)/AUC(0-inf) percentage is less than 80% in more than 20% of the observations, then the validity of the study may need to be discussed in the submission."
- Long half-life drugs (defined as 24 hours or longer): `AUC(0-72h)` becomes the primary AUC parameter and then "the following additional parameters are not required: AUC(0-inf), AUC(0-t)/AUC(0-inf), kel, and t1/2".
- Required summary statistics, verbatim: "number of observations, geometric mean, coefficient of variation, median, arithmetic mean, standard deviation, minimum, and maximum".
- Multiple dose, primary: `CmaxSS` and `AUC(0-tauSS)`; additional: `CtauSS`, `CminSS`, `CavSS`, degree of fluctuation, swing, `tmax`. The glossary defines fluctuation as `(CmaxSS - CminSS) / CavSS` and swing as `(CmaxSS - CminSS) / CminSS`, the definitions `pkpdutils` already uses.
- BLQ, the clearest regulatory statement of a BLQ rule for NCA anywhere, verbatim: "Any concentration reported as below the lower limit of quantification (LLOQ) should be treated as zero in PK parameter calculations. Values below the LLOQ are to be omitted from the calculation of kel and t1/2." Note that this is a blanket zero rule with a single exception, not a first/middle/last rule.
- Partial AUC: `pAUC`, "area under the concentration vs. time curve between two specific time points", is the remedy when Cmax and AUC(0-t) are insufficient.
- Carryover, verbatim: "if there are subjects for whom the pre-dose concentration is greater than 5% of the Cmax value for the subject in that period, then the primary statistical analysis should be performed excluding the data from that period".
- Reporting must state the method, verbatim: "e.g., linear trapezoidal method for AUC and the number of data points of the terminal log-linear phase used to estimate kel".
- At least three points in the terminal log-linear phase; sampling for at least three terminal half-lives unless AUC(0-72h) is used.
- Presentation: two concentration-time graphs, linear and log-linear, for each individual subject on actual times, plus the same pair for the mean profiles on nominal times.
- M13B will cover additional strength biowaivers; **M13C will cover highly variable drugs, narrow therapeutic index drugs and complex designs**, which is where reference scaling will be harmonized.

**FDA, Bioequivalence Studies With Pharmacokinetic Endpoints for Drugs Submitted Under an ANDA**, finalized May 2026 (the 2021 draft is superseded), aligned with M13A. It adds:

- A verbatim reporting list. Single dose: "AUC0-t, AUC0-inf, AUC truncated or partial AUCs if applicable, and Cmax. In addition, report the following supportive information ... Tmax, Kel, and t1/2." Steady state: "AUC0-tau and CmaxSS. In addition, report CminSS ..., CavSS ..., degree of fluctuation [(CmaxSS-CminSS)/CavSS], swing [(CmaxSS-CminSS)/CminSS], and Tmax."
- Cmax "obtained directly from the data (i.e., without interpolation)".
- Datasets: "concentration data in appropriate biological fluid (under **PC domain**), PK parameter data (under **PP domain**)".
- pAUC only "if specified in the applicable PSG"; the windows live in product-specific guidances, not in this document.
- Pre-dose concentration greater than 5 % of Cmax: drop the subject for the affected period.
- **RSABE for highly variable products**: within-subject CV at least 30 %, decision on `sWR` with the cut at 0.294, regulatory constant `sigma_W0 = 0.25`, the 95 % upper confidence bound for `(muT - muR)^2 - theta*sWR^2` must be at most zero, **and** the point estimate must fall within `[0.8000, 1.2500]`. A partial or fully replicate crossover is required.
- **Narrow therapeutic index drugs**: a fully replicate four-way design, `sigma_W0 = 0.10`, and a variability comparison requiring the upper confidence bound for `sWT/sWR` to be at most 2.500.
- **This guidance states no numeric %extrapolated acceptance criterion and no BLQ rule.** Both come from M13A.

**EMA CPMP/EWP/QWP/1401/98 Rev.1** agrees and adds a requirement `pkpdutils` cannot meet at all, verbatim: "When using urinary data, **Ae(0-t)** and, if applicable, **Rmax** should be determined", and "Ae(0-t) should be analysed using the same acceptance interval as stated above for AUC(0-t). Rmax should be analysed using the same acceptance interval as for Cmax." It names the residual area explicitly as a reported parameter and defines it as `(AUC(0-inf) - AUC(0-t)) / AUC(0-inf)`, which is `auc_extrap_fraction` here. It also requires non-compartmental methods outright ("The use of compartmental methods for the estimation of parameters is not acceptable"), demands fixed-effect ANOVA on log transformed data, rejects a non-parametric analysis of AUC and Cmax, and sets `k = 0.760` with the cap 69.84 to 143.19 % for the Cmax-only widening of highly variable products, and 90.00 to 111.11 % for narrow therapeutic index drugs.

**EMA EMA/CPMP/EWP/280/96 Rev1 on modified release dosage forms** is where fluctuation is actually defined (`(Cmax - Cmin)/Cav`), and it is the guideline that requires **`tlag`** for new MR formulations, `Cτ,ss` for generic MR at steady state, and partial AUC, Cmax and tmax **in all phases** for multiphasic products. It also states that "a truncated AUC(0-72h) is not acceptable for MR products".

**CDISC controlled terminology.** The `PKPARMCD` codelist (NCIt C85839, extensible, used by `PPTESTCD`) contains **388 submission values** in the current NCI EVS package. Several of the codes commonly assumed to exist do not: there is no `CLSTP`, no `AEAMT`, no `FE`, no `ACCIND`, no `PTROUGH`, no `CMAXSS`, no `CMINSS`. The real codes confirm which parameters the field considers standard, and several of them `pkpdutils` does not compute:

- **areas**: `AUCALL`, `AUCLST`, `AUCIFO`, `AUCIFP`, **`AUCINT`** (AUC from T1 to T2, the partial AUC code), `AUCTAU`, `AUCPEO`, `AUCPEP`, **`AUCPBEO`/`AUCPBEP`** (percent back extrapolated), and the systematic normalization suffixes `D` dose, `W` weight, `B` BMI, `S` surface area, `UB` unbound, `F` fraction absorbed, giving `AUCLSTD`, `AUCIFOD`, `AUCTAUD`, `CMAXD`, `CAVGD`, `C0D`
- **terminal phase**: `LAMZ`, `LAMZHL`, `LAMZLL`, `LAMZUL`, `LAMZNPT`, **`LAMZSPN`** (the span ratio, which `lambda_z_span` maps to), `R2`, `R2ADJ`, `CORRXY`, **`EFFHL`** (effective half-life), `DISTHL`, `TAUHL`
- **concentrations and times**: `C0`, `CLST`, `CMAX`, `CMIN`, `CAVG`, `CAVGINT`, `CTROUGH`, `TMAX`, `TMIN`, `TLST`, **`TLAG`**, `CONCEINF` (concentration at end of infusion), and **`CHTMAX`/`HTMAX`** (concentration at half tmax and half tmax), which are exactly `pkpdutils`' `cmax_half` and `tmax_half`
- **mean residence time**, split by route, which `pkpdutils` collapses into one name: `MRTEVIFO`/`MRTEVIFP`/`MRTEVLST` extravascular, `MRTIBIFO`/`MRTIBIFP`/`MRTIBLST` IV bolus, `MRTICIFO`/`MRTICIFP`/`MRTICLST` IV continuous infusion, plus `MAT` mean absorption time
- **clearance and volume**: `CLO`, `CLP`, `CLFO`, `CLFP`, **`CLTAU`/`CLFTAU`** (which is `cl_ss`/`cl_ss_f`), `VZO`, `VZP`, `VZFO`, `VZFP`, `VSSO`, `VSSP`, `V0`
- **steady state and accumulation**: **`AILAMZ`** (accumulation index from lambda z), **`ARAUC`**, `ARAUCLST`, `ARAUCIFO`, `ARCMAX`, `ARCMIN`, `ARCTROUG` (observed accumulation ratios on AUC, Cmax, Cmin and Ctrough), `FLUCP`, `SWING`, **`PTROUGHR`** peak to trough ratio, `TROUGHPR`, `RAMAXMIN`, **`SRAUC`** stationarity ratio
- **urine and renal**: `AURCALL`, `AURCLST`, `AURCIFO`, `AURCIFP`, `AURCINT`, `AURCPEO`/`AURCPEP`, **`RCAMINT`**/`RCAMTAU`/`RCAMLST`/`RCAMIFO` (amount recovered), `RCPCINT`/`RCPCTAU`/`RCPCLST` (percent recovered), **`FREXINT`** (fraction excreted), **`RENALCL`**, `RENCLTAU`, `RNCLINT`, `NRENALCL`, `ERMAX`, `ERLST`, `ERINT`, `ERTMAX`, `ERTLST`, `VOLPK`
- **bioavailability and ratios**: `FABS`, `FREL`, `FU`, `FB`, `FM`, and the `RAAUC*`/`RACMAX`/`RACMIN` ratio families

**CDISC ADaM ADNCA v1.0** (published 2021-11-29) is a sub-class of the BDS. Its normative IG is membership gated and was not read; the variable semantics are confirmed from the pharmaverse `admiral` implementation and PharmaSUG papers: `AFRLT` actual relative time from the first dose, `ARRLT` from the reference dose (0 on dosing records, negative pre-dose), `NFRLT`/`NRRLT` the nominal analogues, `ATPTREF`, `PCRFTDTM`, `DOSEA`, `EVID` (0 observation, 1 dose, borrowed from NONMEM), `ABLFL`, `ANL01FL`, and `DTYPE = "COPY"` for records duplicated so one observation can serve two dosing intervals. The `-RLT` suffix is the approved naming; `-TM` is a compliance issue because it implies a clock time. ADNCA adds **subject-level as well as record-level exclusion flags**, which the IG authors call out as a unique and necessary addition.

**Sparse sampling.** No guidance prescribes a method. ICH S3A Q&A acknowledges sparse toxicokinetic sampling and permits "composite AUC and/or Cmax". The estimator comes from the literature: Bailer 1988 for the destructive-sampling AUC and its variance, Nedelman, Gibiansky and Lau 1995 for the sparse-sampling confidence interval accounting for estimated variances, Nedelman and Jia 1998 for the Satterthwaite degrees of freedom, and Holder 2001 for the batch design covariance. The Bailer estimator is `AUC = sum_j w_j * mean_j` with `V[AUC] = sum_j w_j^2 * s_j^2 / n_j` and trapezoidal weights `w_1 = (t_2 - t_1)/2`, `w_j = (t_{j+1} - t_{j-1})/2`, `w_J = (t_J - t_{J-1})/2`, valid under independence across time points; partially serial sampling needs the covariance terms. Phoenix implements Nedelman and Jia with Holder's unbiased covariance and cites Bailer only through the reference list; it requires equal sample sizes per time point, no missing data, and refuses to emit `SE_AUClast`/`SE_AUCall` when a log trapezoidal rule is selected.

**A caution on Beal 2001.** The M1 to M7 methods for below-quantification data are about population model fitting, not NCA. For an NCA BLQ rule the document to cite is ICH M13A.

## 3. What pkpdutils already covers

Measured against the tables above, `pkpdutils` is already competitive on a large part of the surface, and ahead of every surveyed tool on two points.

**Parameter coverage.** The single dose plasma set is essentially complete against Phoenix except for the items listed in section 4: `cmax`, `tmax`, `cmin`, `tmin`, `clast`, `tlast`, `c0`, `cmax_half`/`tmax_half` (which are CDISC `CHTMAX`/`HTMAX`, and which neither Phoenix nor Pumas reports), `auc_last`, `auc_inf_obs`, `auc_inf_pred`, `auc_extrap_fraction` (the EMA residual area), `aumc_last`, `aumc_inf`, `mrt` with the infusion correction, `lambda_z` with eight diagnostics, `thalf`, `cl`/`cl_f`, `vz`/`vz_f`, `vss`, `auc_inf_dn`, `cmax_dn`.

**Methods.** All three trapezoid rules including linear up/log down. Terminal phase selection by best adjusted R2 with `tie_tolerance` defaulting to 1e-4, which is exactly the 0.0001 rule that Phoenix and PKanalix both implement verbatim and that Pumas apparently does not: this is the single most portable detail in the whole survey, and getting it right means `No_points_lambda_z` agrees with the commercial tools on flat tails. `min_points` defaults to 3 and `exclude_cmax` to True, matching the Phoenix rule that points before Cmax and the Cmax point itself are excluded for non-bolus models. The span ratio is computed as `lambda_z_span` and flagged below 2, which matches the Phoenix definition `(Lambda_z_upper - Lambda_z_lower) / HL_Lambda_z` and the CDISC code `LAMZSPN`.

**Multiple dosing.** The per-interval analysis over an `interval` dimension is more granular than what Phoenix, PKanalix or Pumas expose by default, and none of them reports an observed accumulation ratio at all: `accumulation_ratio_obs` corresponds to CDISC `ARAUC`, which Phoenix, PKanalix and Pumas all lack (they report only the theoretical `1/(1 - exp(-lambda_z*tau))`, which `pkpdutils` also has). The steady state block covers the M13A multiple dose list apart from the dose normalized and tau variants. `superposition` and the two `accumulation_ratio` forms are present. The reference dose rule, where the point parameters come from the last dose on and single dose quantities are suppressed, is stricter and better documented than anything the surveyed tools state.

**Uncertainty.** Bootstrap and delta propagation of `sd`/`se` from group mean curves into every parameter, with `x_sd`, `x_se`, `x_ci_low`, `x_ci_high`, `x_geomean`, `x_geocv`, `x_pi_low`/`x_pi_high`, is offered by no tool surveyed. PKNCA and Phoenix summarize individuals; they do not propagate the uncertainty of a digitized literature mean curve. This is the genuine differentiator and it is what the meta-analysis use case needs.

**Statistics.** Nothing else in the survey combines NCA with parameter statistics in one library: two sample and paired tests with effect sizes, geometric mean ratios, TOST and average bioequivalence with 2x2 crossover detection and the within-subject CV, the FDA and EMA DDI classification, and a DerSimonian-Laird meta-analysis with heterogeneity. PKNCA has a bioequivalence vignette; PowerTOST and replicateBE are separate packages; `pkr` has bioequivalence but not meta-analysis or DDI.

**Formats.** Three readers (NONMEM/Monolix event records with ADDL/II/SS expansion, the PKNCA two-table layout, CDISC ADaM ADNCA) against PKNCA's one and Phoenix's import dialogs.

**Units.** pint throughout with units on every result variable, which puts `pkpdutils` in the same class as Pumas (Unitful) and ahead of every R tool except PKNCA's preferred-unit table, and far ahead of every python package, none of which carries units at all.

**Reporting and figures.** `summary_table` with the geometric mean and CV convention, `ratio_table`, `ddi_table`, rich console rendering, and a plotting module with NCA diagnostic panels, grids, interval and trough plots, fit diagnostics, forest and ratio plots. Note that Phoenix produces exactly one plot type.

**Engineering.** Vectorized over a whole batch with chunking and a thread pool, `xarray` results with units and flags, full type annotations, a ty clean tree. No R tool is vectorized this way, and the Pumas platform paper's own headline is a 210x speed advantage over PKNCA, which suggests speed is a differentiator worth keeping.

### 4.6 Suggested order

1. Features 1 to 7 as one pull request: the missing parameters and the BLQ rules. All small, all named by a guidance or by every comparator, no architectural change.
2. Features 8, 9, 25, 26 as a second: acceptance criteria and exclusions, named partial AUCs, the M13A report package and the carryover check. These are what makes the output usable in a regulatory context and they build on each other.
3. Feature 31, the published validation. It is not a feature, it is the thing that makes every other feature trustworthy, and it is cheap relative to its value. Two single-author python packages have already done it.
4. Features 15 to 20: the steady state completion. Small individually, and they finish the multiple dose story the package already tells better than the commercial tools.
5. Feature 12 (urine, with native renal clearance as the differentiator) and feature 13 (sparse sampling). The two structural gaps. Urine needs a collection-interval data type, sparse sampling needs a design concept; both deserve a design document of their own.
6. Features 21 to 24: analytes, the CDISC name map and the writers.
7. Features 28 to 30 and 32: the bioequivalence completion and the report. Largest effort, and the one place where a good R implementation (PowerTOST, replicateBE) can reasonably be pointed to in the meantime.

Items carrying an explicit caveat: feature 16, where the effective half-life formula should be read from the PKNCA source rather than reconstructed; feature 11, where the per-sample window record format is a design decision not settled by any comparator; and feature 22, where the full 388-value `PKPARMCD` list should be parsed from the NCI EVS tab-delimited package rather than transcribed.

## 5. Corrections to widely held beliefs, verified during this survey

These were checked against primary sources and contradict what is commonly assumed, including in the brief that commissioned this survey. They matter because several would produce wrong code if assumed.

- **Phoenix has no `PTF` parameter.** It is `Fluctuation%` and `Fluctuation%_Tau`, with the percent sign inside the name. PKanalix spells the same thing `FluctuationPerCent`.
- **Phoenix has no `Ae`, no `Ae%` and no `CLr`.** The urine amounts are `Amount_Recovered` and `Percent_Recovered`, and a grep of the whole 8.3 User's Guide for "CLr", "renal clearance" and "Renal" returns nothing. Renal clearance is built in the separate Ratios and Differences object or as a user defined parameter. PKanalix and Pumas also lack a built-in renal clearance.
- **There is no Phoenix "Model 221".** Model 220 is the Drug Effect (PD) model. Steady state is not a model number at all: it is triggered by mapping a `Tau` column on models 200 to 202. Sparse sampling is a checkbox, not a model.
- **Phoenix has no pure log trapezoidal option**, and its two "Linear Trapezoidal" variants differ only in how a partial-area endpoint is interpolated, not in the main AUC.
- **Phoenix's Validation Suite is explicitly not a Part 11 control.** Its own guide states: "The Validation Suite tests do not provide the appropriate technical controls to ensure a 21 CFR Part 11 compliant implementation." Part 11 comes from the Phoenix Knowledgebase Server or Certara Integral.
- **PKanalix does not claim 21 CFR Part 11, an audit trail or IQ/OQ anywhere in its public documentation.**
- **Pumas's `interval` argument has no effect inside `run_nca`**, so partial AUCs must be computed separately; and its documented sparse support is a boolean flag with no method behind it in the docs.
- **No 0.0001 adjusted-R2 tie-break could be verified in Pumas**, where Phoenix and PKanalix both implement it verbatim. If that holds, the three tools disagree on `No_points_lambda_z` for flat tails. `pkpdutils` already sides with Phoenix and PKanalix.
- **BLQ semantics do not port between tools.** Phoenix substitutes codes with no positional logic, PKanalix splits before and after tmax, Pumas and PKNCA split first, middle and last relative to measurable values. A round trip between any two of them silently changes the result.
- **`Certara.NCA` and `certara.github.io/R-NCA` do not exist.** The URL 404s and no NCA package appears among Certara's 35 GitHub repositories or 11 r-universe packages.
- **Several assumed CDISC codes do not exist**: `CLSTP`, `AEAMT`, `FE`, `ACCIND`, `PTROUGH`, `CMAXSS`, `CMINSS`. The real ones are `CLST`, `RCAMINT`, `FREXINT`, `AILAMZ`, `PTROUGHR`, and there are no steady-state-specific Cmax or Cmin codes.
- **Beal 2001 (M1 to M7) is about population model fitting, not NCA.** For an NCA BLQ rule the document is ICH M13A.
- **The FDA ANDA bioequivalence guidance was finalized in May 2026** and states no %extrapolated criterion and no BLQ rule of its own; both come from M13A.
- **`pharmpy`, the only widely used python pharmacometrics package, has no NCA at all.** There is no incumbent python NCA package to displace.
