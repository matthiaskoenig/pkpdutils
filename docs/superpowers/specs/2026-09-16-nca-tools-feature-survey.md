# Non-compartmental analysis tools: feature survey and suggested features for pkpdutils

Date: 2026-09-16. Status: read-only survey, no code change. Scope: what the other non-compartmental analysis (NCA) tools compute and offer, what `pkpdutils` 1.1 already covers, and a prioritized list of features with an effort estimate and the module they would live in.

Every claim below is either taken from a page listed under [References](#references) and read during this survey, or is read from the source tree of this repository. Where a claim could not be verified from a primary source it says so explicitly; nothing here is filled in from memory.

## 1. Tools surveyed

Eleven tools besides `pkpdutils`, in four families.

**R.** `PKNCA` (Bill Denney, the de facto open source reference implementation), `aNCA` (pharmaverse, a Shiny front end on PKNCA sponsored by Roche), `ubiquity` (a thin wrapper around PKNCA for preclinical reporting), `NonCompart`/`ncar` (Kyun-Seop Bae, WinNonlin parameter naming and CDISC output), `ncappc` (NCA plus simulation based posterior predictive checks against a population model), `PK` (the sparse and batch design estimators of Bailer, Nedelman, Holder, Jaki and Wolfsegger), and `PowerTOST`/`replicateBE` (bioequivalence statistics rather than NCA, included because they define what "complete" means on the statistics side).

**Commercial.** `Phoenix WinNonlin` (Certara) and `PKanalix` (MonolixSuite, Simulations Plus).

**Julia.** `Pumas` NCA.

**Python.** There is no established python NCA package. The search of PyPI and GitHub found only `noncompartmental` (a pure standard library module returning AUC, AUMC, MRT, the terminal rate and half-life, Cmax/Tmax, clearance and Vss), `PKPy` (a population PK framework that computes AUC, Cmax and the terminal half-life as a side product) and `pk-nca` (a browser based calculator that exports an R and a python script). None of them is a maintained library with the parameter breadth of the tools above. This is the gap `pkpdutils` sits in, and it is the reason the rest of this document measures against R, Julia and the commercial tools rather than against python.

### 2.3 Regulatory and standards expectations

**ICH M13A** (adopted 2024, issued by FDA as guidance) is now the harmonized baseline and it is precise about what an NCA must deliver.

- Single dose, primary parameters for the bioequivalence analysis: `AUC(0-t)` and `Cmax`, plus early exposure parameters where applicable.
- Single dose, additional parameters to assess acceptability of the study: `AUC(0-inf)`, `AUC(0-t)/AUC(0-inf)`, `tmax`, `kel`, `t1/2`.
- Acceptability rule: "For single-dose studies, AUC(0-t) should cover at least 80% of AUC(0-inf). If the AUC(0-t)/AUC(0-inf) percentage is less than 80% in more than 20% of the observations, then the validity of the study may need to be discussed in the submission."
- Long half-life drugs: `AUC(0-72h)` becomes the primary AUC parameter and then "the following additional parameters are not required: AUC(0-inf), AUC(0-t)/AUC(0-inf), kel, and t1/2".
- Required summary statistics: "number of observations, geometric mean, coefficient of variation, median, arithmetic mean, standard deviation, minimum, and maximum".
- Multiple dose, primary: `CmaxSS` and `AUC(0-tauSS)`; additional: `CtauSS`, `CminSS`, `CavSS`, degree of fluctuation, swing, `tmax`. The glossary defines fluctuation as `(CmaxSS - CminSS) / CavSS` and swing as `(CmaxSS - CminSS) / CminSS`, which are the definitions `pkpdutils` already uses.
- BLQ: "Any concentration reported as below the lower limit of quantification (LLOQ) should be treated as zero in PK parameter calculations. Values below the LLOQ are to be omitted from the calculation of kel and t1/2."
- Partial AUC: `pAUC`, "area under the concentration vs. time curve between two specific time points", is the tool for cases where Cmax and AUC(0-t) are insufficient.
- Carryover: "if there are subjects for whom the pre-dose concentration is greater than 5% of the Cmax value for the subject in that period, then the primary statistical analysis should be performed excluding the data from that period".
- Reporting must state the method: "e.g., linear trapezoidal method for AUC and the number of data points of the terminal log-linear phase used to estimate kel".

**EMA CPMP/EWP/QWP/1401/98 Rev.1** agrees and adds one requirement `pkpdutils` cannot meet at all: "When using urinary data, Ae(0-t) and, if applicable, Rmax should be determined", and "Ae(0-t) should be analysed using the same acceptance interval as stated above for AUC(0-t). Rmax should be analysed using the same acceptance interval as for Cmax." It also names the residual area explicitly as a reported parameter and defines it as `(AUC(0-inf) - AUC(0-t)) / AUC(0-inf)`, which is `auc_extrap_fraction` here.

**CDISC controlled terminology** (`PKPARMCD`, NCI code C85839, extensible) carries 394 submission values in the 2026-03-27 SDTM terminology release. The codes confirm which parameters the field considers standard, including several `pkpdutils` does not compute: `AUCALL`, `AUCINT` (interval AUC), `AUCPBEO` and `AUCPBEP` (percent back-extrapolated), `TLAG`, `EFFHL` (effective half-life), `DISTHL`, `RAAUC` (accumulation ratio on AUC), `PTROUGHR` (peak to trough ratio), `CLTAU` and `CLFTAU`, `CAVGINT`, the dose normalized `*D` family (`AUCLSTD`, `AUCIFOD`, `AUCTAUD`, `CMAXD`, `CAVGD`, `C0D`), the three MRT families `MRTEV*` (extravascular), `MRTIB*` (IV bolus) and `MRTIC*` (IV infusion), and the whole excretion block `AURC*` (area under the rate curve), `RCAM*` (recovered amount), `RCPC*` (recovered percent), `RENALCL` and `VOLPK`.

## 3. What pkpdutils already covers

Measured against the tables above, `pkpdutils` is already competitive on a large part of the surface, and ahead of every surveyed tool on two points.

**Parameter coverage.** The single dose plasma set is essentially complete against Phoenix except for the items listed in section 4: `cmax`, `tmax`, `cmin`, `tmin`, `clast`, `tlast`, `c0`, `auc_last`, `auc_inf_obs`, `auc_inf_pred`, `auc_extrap_fraction` (the EMA "residual area"), `aumc_last`, `aumc_inf`, `mrt` with the infusion correction, `lambda_z` with eight diagnostics, `thalf`, `cl`/`cl_f`, `vz`/`vz_f`, `vss`, `auc_inf_dn`, `cmax_dn`.

**Methods.** All three trapezoid rules including linear up/log down. Terminal phase selection by best adjusted R2 with a tie tolerance that prefers more points, exactly the Phoenix rule, plus last n, all after tmax and manual, with `min_points`, `exclude_cmax` and `min_adj_r2`. The span ratio is computed (`lambda_z_span`) and flagged below 2, which matches the Phoenix `Span` definition `(Lambda_z_upper - Lambda_z_lower) / HL_Lambda_z`.

**Multiple dosing.** The per-interval analysis over an `interval` dimension is more granular than what Phoenix, PKanalix or Pumas expose by default, and the steady state block (`auc_tau`, `cavg`, `ctrough`, `cmin_ss`, `cmax_ss`, `fluctuation`, `swing`, `accumulation_ratio`, `accumulation_ratio_obs`, `cl_ss`, `cl_ss_f`) covers the M13A multiple dose list apart from the dose normalized and `tau` variants. `superposition` and the two `accumulation_ratio` forms are present. The reference dose rule (point parameters from the last dose on, single dose quantities suppressed) is stricter and better documented than what the surveyed tools state.

**Uncertainty.** Bootstrap and delta propagation of `sd`/`se` from group mean curves into every parameter, with `x_sd`, `x_se`, `x_ci_low`, `x_ci_high`, `x_geomean`, `x_geocv`, `x_pi_low`/`x_pi_high`, is not offered by any tool surveyed. PKNCA and Phoenix summarize individuals; they do not propagate the uncertainty of a digitized literature mean curve. This is `pkpdutils`' genuine differentiator, and it matters for the meta-analysis use case the package was built for.

**Statistics.** Nothing else in the survey combines NCA with the parameter statistics in one library: two sample and paired tests with effect sizes, geometric mean ratios, TOST and average bioequivalence with 2x2 crossover detection and the within-subject CV, the FDA and EMA DDI classification, and a DerSimonian-Laird meta-analysis with heterogeneity. PKNCA has a bioequivalence vignette; PowerTOST and replicateBE are separate packages.

**Formats.** Three readers (NONMEM/Monolix event records with ADDL/II/SS expansion, the PKNCA two-table layout, CDISC ADaM ADNCA) against PKNCA's one and Phoenix's import dialogs.

**Reporting and figures.** `summary_table` with the geometric mean and CV convention, `ratio_table`, `ddi_table`, rich console rendering, and a plotting module with NCA diagnostic panels, grids, interval and trough plots, fit diagnostics, forest and ratio plots.

**Engineering.** Vectorized over a whole batch with chunking and a thread pool, `xarray` results with units, full type annotations, a ty clean tree. None of the R tools is vectorized this way.

## 4. Suggested features, prioritized

Effort: **S** about a day, **M** a few days, **L** a week or more including tests, docs and examples.

| 13 | sparse sampling | mean curve NCA with standard errors for destructive or batch designs: the Bailer estimator, the Nedelman and Jia correction, and the Holder batch design covariance; designs `serial`, `batch`, `complete` | Phoenix sparse sampling for models 200 to 202 and 210 to 212, citing Nedelman and Jia 1998 and Holder 2001, with standard errors on Cmax, AUClast, AUCall, Max_Rate and AURC_all; PKNCA `pk.calc.sparse_auc`, `pk.calc.sparse_aumc` and a sparse vignette; Pumas `sparse = true`; the whole R package `PK` (designs `"ssd"`, `"batch"`, `"complete"`, intervals `"t"`, `"z"`, `"boott"`). ### 4.6 Suggested order

1. Features 1 to 7 as one pull request: the missing parameters and the BLQ rules. All small, all named by a guidance or by every comparator, no architectural change.
2. Features 8, 9, 25, 26 as a second: acceptance criteria, exclusions, named partial AUCs and the M13A report package. Together these are what makes the output of `pkpdutils` usable in a regulatory context, and they build on each other.
3. Features 14 to 19: the steady state completion. Small individually, and they finish the multiple dose story the package already tells well.
4. Feature 12 (urine) and feature 13 (sparse sampling). The two structural gaps. Urine needs a collection-interval data type, sparse sampling needs a design concept; both are worth a design document of their own.
5. Features 20 to 24: analytes, the CDISC name map and the writers.
6. Features 28 to 31: the bioequivalence completion and the report. Largest effort, and the one place where a good R implementation already exists that a user can reasonably be pointed to in the meantime.

Features 10, 11 and 15 carry an explicit caveat: the exact rule (the Phoenix `C0` fallback chain, the per-sample window record format, the effective half-life formula) should be settled against the primary source before implementation, because this survey read the parameter definitions but not every computation rule page.
